# 9.3 硬件控制域与 SFP 设备服务

主控处理器 VPE0 协调 GPON 数据通路、光物理层和 SFP 管理服务。寄存器访问、管理消息处理与报文注入是三种不同的控制方式；主控侧的设备接口和命令编号由运行环境定义，不属于 SoC 固有寄存器。

## 1. 控制域

| 控制域 | 硬件资源 | 主控职责 |
| --- | --- | --- |
| GPON 成帧与激活 | GTC，物理基址 0x1DC00000 | 帧同步、PLOAM 状态、测距、序列号和密码、误码统计、掉电告警 |
| 报文处理 | GPE、SCE、IQM、TMU、TBM、SSB0 | 微码启动、缓冲水位、GEM/T-CONT 映射、队列、调度、计量和转发表 |
| UNI 侧链路 | EIM、SGMII/SXGMII、GPHY | 接口模式、速率、自协商、PAUSE 和链路状态 |
| 光模拟前端 | PMA 0x1DD00000、FCSIC 0x1DD00600 | 光路状态、测量、突发激光门控与校准闭环 |
| 电源 | DCDC_CORE 0x1E803000、DCDC_DDR 0x1E804000、DCDC_APD 0x1E805000 | 电源目标值、APD 偏压和温度补偿 |
| SFP 管理 | VPE1、I2C、共享 SRAM | 外部宿主的 EEPROM 访问、诊断值和软控制通知 |

## 2. 控制操作的依赖

数据通路配置通常先建立时钟与复位条件，再装载微码、初始化缓冲和队列，最后激活端口。GEM Port-ID、GPIX 和 T-CONT 索引是不同的标识空间，配置时必须保持它们与调度树的关联。

光路配置需要有效的单板校准数据。测量模块提供电压、电流、温度与光功率观测；MPD/BOSA 闭环调节偏置和调制量，APD 电源根据温度补偿偏压。寄存器可访问并不表示光路已校准，主控必须检查就绪状态和告警。

## 3. VPE0–VPE1 SFP 设备服务协议 (`0x1F200200`)

以下布局属于 MA5671A 的 SFP 设备服务协议，不是 Falcon SoC 固定的寄存器布局。VPE1 与 VPE0 通过位于 `SBS0` 的固定共享内存区（物理地址 `0x1F200200`，KSEG0 虚拟地址 `0x9F200200`，总长 `0x7AC` = 1964 字节）交换 SFF-8472 双地址（`0xA0`/`0xA2`）EEPROM 数据与状态。

### 3.1 共享内存布局 (`0x1F200200`, 1964 B)

共享内存区包含两个对称的 976 字节 EEPROM 银行结构（`Bank 0` 对应从地址 `0xA0`，`Bank 1` 对应从地址 `0xA2`）及 12 字节全局控制尾：

| 字节偏移 | 字段名称 | 大小 | 硬件与协处理器交互说明 |
| --- | --- | --- | --- |
| `+0x000` | 当前偏移 | 1 B | 当前 I2C 偏移 |
| `+0x001` | EEPROM 镜像 | 640 B | EEPROM 镜像 |
| `+0x281` | 写保护掩码 | 256 B | 逐字节写保护掩码 |
| `+0x381` | 写事件位图 | 32 B | 256 位写事件 bitmap |
| `+0x3A1` | 读事件位图 | 32 B | 256 位读事件 bitmap |
| `+0x3C1` | 状态 / 地址 / 通知标志 | 各 1 B | 状态、从机地址与通知使能 |
| `+0x3C4` | 访问码 | 4 B | 访问码 |
| `+0x3C8` | 保留字段 | 4 B | 保留 |
| `+0x3CC` | 访问模式 | 4 B | 访问模式 |
| `+0x3D0`–`+0x79F` | 诊断 bank (`0xA2` DDM 区) | 976 B | 结构与 标识 bank 相同，存放 SFF-8472 `0xA2` 诊断监控值、阈值、软控制位与扩展页 |
| `+0x7A0` | SDA 引脚号 | 4 B | I2C SDA 绑定的 GPIO 编号（缺省 `39`） |
| `+0x7A4` | SCL 引脚号 | 4 B | I2C SCL 绑定的 GPIO 编号（缺省 `40`） |
| `+0x7A8` | 事务处理使能 | 4 B | VPE1 从机事务处理总使能标志（`1` = 运行，`0` = 挂起） |

读写事件按位读取并清除；事件区不是事务计数器。读取位与清除位是分开的操作，不能将其当作原子的全区快照。0xA0/0xA2 是 8 位地址表示，对应总线 7 位地址 0x50/0x51。两个处理单元必须采用一致的数据布局、地址表示和事件清除规则。


## 4. CPU 报文通道与逻辑端口

ICTRLC0/1 的物理基址为 0x1D461000/0x1D461100，OCTRLC 为 0x1D441000。它们提供 CPU 与 GPE 之间的报文注入和提取通道。

设备服务可以在这些通道上划分 host、本地维护、异常报文和调试端口。host、lct0–lct3、exc、dbg、dbc 是逻辑用途，名称及端口编号取决于系统配置，不代表额外的物理 MAC。MA5671A 仅有一个 UNI 连接，不能由逻辑端口数量推导外部接口数量。

OMCI 管理流量使用专用 GEM 通道及 Q7；Q8 用于 CPU 向 LAN 注入。主控应区分接收队列、出向端口和本地网络接口，避免把三个编号空间混为一谈。
