# 5.3 PE 64 位指令、寄存器与调试接口

PE 核心执行 64 位大端指令。在 32 位主机总线窗口 `PE[pe_idx].PROG[8192]`（偏移 `0x8000`–`0xFFFF`）中，每条 64 位指令按大端序拆分为两个连续的 32 位字：字节地址 `address` 右移 2 位得到字下标 `w = address >> 2`，`PROG[w + 0]` 存放指令高 32 位（bit 63:32），`PROG[w + 1]` 存放指令低 32 位（bit 31:0）。

## 1. 寄存器模型

PE 架构包含 16 个可通过单条访存指令读出的 32 位物理寄存器（编号 0–15），以及全局基址指针 `%gp`、条件标志位 `%t`、程序计数器 `%pc` 和 8 级硬件循环调用栈（`%l0`–`%l7`、`%sp`）：

| 寄存器编号 | 汇编名称 | 硬件性质 | 功能与位域说明 |
| --- | --- | --- | --- |
| 0–12 | `%r0`–`%r12` | 32 位通用寄存器 | 算术逻辑运算与数据暂存 |
| 13 | `%zero` (`%r13`) | 零寄存器 / 寄存器 13 | 访存指令助记符标为 `%zero` |
| 14 | `%fp` (`%r14`) | 32 位帧指针寄存器 | 局部数据寻址帧指针 |
| 15 | `%st` (`%r15`) | 32 位状态与控制寄存器 | 包含当前 PC、条件位 `%t` 及调用栈底标志（bit 23）。单步读出 `%st` 时需加 8 得到当前值；写入前需先减 8 |
| 16 | `%gp` | 全局基址寄存器 | 与 `%r15` 共享物理槽位，通过专用指令 `mova` 经通用寄存器读写 |
| 17 | `%t` | 1 位条件谓词标志 | 对应 `%st` 的 bit 0（`%st & 1`），控制条件分支与 LSU 条件执行 |
| 18 | `%pc` | 16 位程序计数器 | 对应 `%st` 的 bit 15:3（掩码 `0xFFF8`），按 8 字节（64 位指令）对齐 |
| 19–26 | `%l0`–`%l7` | 8 级硬件调用栈 | 存放 `call` 指令压入的返回地址，由 `call` / `return` 循环压栈与弹出 |
| 27 | `%sp` | 3 位调用栈指针 | 指示当前调用栈层级 `(8 - sp) & 7` |

## 2. 64 位指令编码

### 2.1 间接加载与存储指令 (`ld.i` / `st.i`)

`ld.i` 与 `st.i` 用于在 PE 寄存器与主机接口窗口（`HOST_DATA0` 起，即 `HOST[]`）或 PE 本地数据 RAM 之间传输 32 位字：

| 位域 | 宽度 | 字段名 | 编码说明 |
| --- | --- | --- | --- |
| `63:41` | 23 位 | 本组调试指令固定高位 | `0` |
| `40:35` | 6 位 | 本组调试指令固定操作码 | `0b101100`（`0x2C`），由所列指令常量提取；不扩展为完整 ISA 规范 |
| `34` | 1 位 | `L`（方向） | `0` 为存储 `st.i`，`1` 为加载 `ld.i` |
| `33:29` | 5 位 | `reg` | 源或目的寄存器编号（`0`–`15` 对应 `%r0`–`%st`） |
| `28:24` | 5 位 | `base` | 基址选择：`0x1a` 为主机窗口 `[HOST_DATA0 + offset]`；`0x14`（`10 << 1`）为寄存器间接寻址 `[%r10]` |
| `23:20` | 4 位 | `offset` | 主机窗口字索引（`HOST[offset]`，对应字节偏移 `offset * 4`） |
| `19:0` | 20 位 | 保留 | `0x00000` |

### 2.2 算术、专用寄存器传送与控制流指令

| 助记符 | 64 位指令字 | 硬件行为 |
| --- | --- | --- |
| `and %r10, %r10, 1` | `0xd0aa020000000000` | `%r10 = %r10 & 1`（高 32 位 ALU 槽编码操作码与源/目的寄存器） |
| `mov %t, %r10` | `0xd7da020000000000` | 将 `%r10` 低位写入条件标志 `%t` |
| `mova %r10, %gp` | `0x000000b15e000000` | 读取全局基址寄存器 `%gp` 至 `%r10` |
| `mova %gp, %r10` | `0x000000b1f4000000` | 将 `%r10` 写入全局基址寄存器 `%gp` |
| `call 0` | `0x0000000000019000` | 将返回地址压入 8 级硬件调用栈并跳转至地址 0 |
| `goto %r10` | `0x000000000001c00a` | 寄存器间接跳转至 `%r10`（低 4 位 `0xa` 指定寄存器 `%r10`） |
| `return` | `0x000000000001e000` | 从 8 级硬件调用栈弹出返回地址并装入 `%pc` |

## 3. 硬件调试模式与指令注入机制

当某台虚拟机在 `PCTRL.TCTRL0` 中暂停且在 `PCTRL.TDEBUG0` 中置位调试模式时，该虚拟机忽略 `%pc`，每次对 `PCTRL.TSTEP0` 写 1 均固定取指并执行 `PROG[0..1]`（字节地址 0）处的 64 位指令，同时不推进 `%pc`。利用这一硬件机制可执行以下操作：

- **读通用寄存器**：向 `PROG[0..1]` 写入 `st.i %rN, [HOST_DATA0]`，触发一次 `TSTEP0`，从 `HOST[0]` 读出寄存器值。
- **写通用寄存器**：将目标值写入 `HOST[0]`，向 `PROG[0..1]` 写入 `ld.i %rN, [HOST_DATA0]`，触发一次 `TSTEP0`。
- **读写 `%gp`**：先保存 `%r10`，单步执行 `mova %r10, %gp` + `st.i %r10, [HOST_DATA0]`（或 `ld.i %r10, [HOST_DATA0]` + `mova %gp, %r10`），再恢复 `%r10`。
- **写 `%t` / `%pc` / `%st`**：先保存 `%r10`；写 `%t` 执行 `ld.i %r10, [HOST_DATA0]` → `and %r10, %r10, 1` → `mov %t, %r10`；写 `%pc` 执行 `ld.i %r10, [HOST_DATA0]` → `goto %r10`；写 `%st` 将 `data - 8` 放入 `HOST[0]` 后依次执行上述 5 条指令；最后恢复 `%r10`。
- **读写数据 RAM**：保存 `%r10`（及 `%r11`），通过 `HOST[0]` 将目标地址装入 `%r10`，再单步执行 `ld.i %r10, [%r10]` 或 `st.i %r11, [%r10]`。
- **读取 8 级硬件调用栈**：先保存 `%st`，循环 8 次（`i = 7 .. 0`）单步执行 `return`（`0x000000000001e000`）并读取 `%st`：若读出的 `%st` 的 bit 23 为 1，则记录栈底位置 `sp = i`；每级栈项地址为 `(st - 8) & 0xFFF8`；循环 8 次后调用栈旋转一圈回到原位，最后恢复 `%st`。
- **指令断点位（bit 17）**：64 位指令字低 32 位的 bit 17（`1ULL << 17`）为指令内嵌断点标志位。当 `PCTRL.BCTRL0` 对应位置 1 且执行到 bit 17 为 1 的指令时，虚拟机停在该指令上并将 `PCTRL.BSTAT0` 置 1。

## 4. 主机至 PE 的邮箱协议 (`HOST[]` 与 `ISIG`)

在运行状态下，主机与 PE 通过 `HOST[0]`–`HOST[9]` 及 `PCTRL.ISIG0`–`ISIG2` 进行同步消息通信。

### 4.1 局部表读写消息协议 (`HOST[1]`–`HOST[9]`)

主机向 PE 写入表项时，先将最多 8 个 32 位数据字写入 `HOST[2]`–`HOST[9]`，再将 32 位命令头写入 `HOST[1]`（读取表项时直接写 `HOST[1]`，完成后从 `HOST[2]`–`HOST[9]` 读出数据）。`HOST[1]` 的位域格式如下：

| 位域 | 宽度 | 字段名 | 说明 |
| --- | --- | --- | --- |
| `31` | 1 位 | `W` | `1` 为写表项，`0` 为读表项 |
| `30` | 1 位 | `RVAL` | 响应有效标志：主机发命令时写 `0`，PE 处理完毕后将该位置 `1` |
| `29:25` | 5 位 | `T_NUM` | PE 局部表编号（`table_id`） |
| `24:21` | 4 位 | `LENGTH` | 表项宽度（32 位字数减 1，即 `entry_width - 1`） |
| `20:2` | 19 位 | `BYTE_OFFSET` | 表内字偏移左移 2 位，即 `(table_idx * entry_width) << 2` |
| `1:0` | 2 位 | `ERR` | bit 0 为错误标志（命令完成后在 `HOST[0]` 的 bit 0 检查 `CMD_ERR`） |

写入 `HOST[1]` 后，主机通过 `PCTRL.ISIG0`–`ISIG2` 向目标 PE 注入唤醒信号（`ISIG1`、`ISIG2` 为影子寄存器，写完后必须向 `ISIG0` 写 `0` 触发发送）：

| 目标 PE | 唤醒目标线程 | 影子寄存器写入操作 | 触发寄存器写入操作 |
| --- | --- | --- | --- |
| PE0 | 线程 0 (`THREAD_0_0_0`) | 无 | `ISIG0 = 0x00000001` |
| PE1 | 线程 16 (`THREAD_1_0_0`) | 无 | `ISIG0 = 0x00010000` |
| PE2 | 线程 32 (`THREAD_2_0_0`) | `ISIG1 = 0x00000001` | `ISIG0 = 0x00000000` |
| PE3 | 线程 48 (`THREAD_3_0_0`) | `ISIG1 = 0x00010000` | `ISIG0 = 0x00000000` |
| PE4 | 线程 64 (`THREAD_4_0_0`) | `ISIG2 = 0x00000001` | `ISIG0 = 0x00000000` |
| PE5 | 线程 80 (`THREAD_5_0_0`) | `ISIG2 = 0x00010000` | `ISIG0 = 0x00000000` |

随后主机轮询 `HOST[1]` 的 bit 30（`RVAL`）变为 1，并检查 `HOST[0]` 的 bit 0（`ERR`）是否为 0。

### 4.2 `HOST[0]` 单字握手与命令编码

`HOST[0]` 同时支持单字握手传输：等待 `HOST[0]` 的 bit 30（`RVAL`）为 0 后，写入 `(pe_index << 27) | pdata`（低 16 位为载荷），等待 PE 将 `HOST[0]` 的 bit 30 置 1，读取 `HOST[0]` 的低 16 位与 bit 0（`ERR`），最后向 `HOST[0]` 写 0 清除握手状态。相关命令编码定义如下：

| 命令名称 | 编码 | 命令名称 | 编码 |
| --- | --- | --- | --- |
| `CMD_NOTHING` | `0x00` | `CMD_RGPH` | `0x1D` |
| `CMD_SET_ADDR` | `0x01` | `CMD_RGPL` | `0x1E` |
| `CMD_MEM` | `0x02` | `CMD_R15H` | `0x1F` |
| `CMD_R0H` / `CMD_R0L` | `0x03` / `0x04` | `CMD_RPC` | `0x20` |
| `CMD_R11H` / `CMD_R11L` | `0x19` / `0x1A` | `CMD_IRQ_REASON` | `0x21` |
| `CMD_RFPH` / `CMD_RFPL` | `0x1B` / `0x1C` | `CMD_STOP` / `CMD_REG_PREPARE` | `0xFF` / `0x3FF` |
