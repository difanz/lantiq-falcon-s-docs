# 5.2 PE 微架构、虚拟机与 PCTRL

SCE 内含 6 颗对称的 64 位处理单元（Processing Element，PE0–PE5）。每颗 PE 在 SBS2 总线上占用独立的 64 KiB 地址窗口，步长为 `0x10000`（`0x4000` 个 32 位字）。

| PE 编号 | 物理基址 | 物理结束地址 | KSEG1 虚拟基址 |
| --- | --- | --- | --- |
| PE0 | `0x1D610000` | `0x1D61FFFF` | `0xBD610000` |
| PE1 | `0x1D620000` | `0x1D62FFFF` | `0xBD620000` |
| PE2 | `0x1D630000` | `0x1D63FFFF` | `0xBD630000` |
| PE3 | `0x1D640000` | `0x1D64FFFF` | `0xBD640000` |
| PE4 | `0x1D650000` | `0x1D65FFFF` | `0xBD650000` |
| PE5 | `0x1D660000` | `0x1D66FFFF` | `0xBD660000` |

## 1. 单颗 PE 的 64 KiB 地址空间布局

每颗 PE 的 64 KiB 主机窗口划分为 4 个连续的地址区：

| 区域名称 | 窗口内字节偏移 | 32 位字数 | 寄存器位域定义与硬件功能 |
| --- | --- | --- | --- |
| `HOST` | `0x0000`–`0x3FFF` (16 KiB) | 4096 | bit 30:0 `HOSTREG`（掩码 `0x7FFFFFFF`）。主机接口地址空间，`HOST[0]`–`HOST[9]` 用作主机与 PE 间的命令/数据邮箱及调试传值窗口 |
| `BREAKP` | `0x4000`–`0x5FFF` (8 KiB) | 2048 | bit 31 `BREAK_EN`（`0x80000000`，硬件断点使能）；bit 13:3 `BREAKP`（掩码 `0x00003FF8`，触发硬件断点的目标 PC） |
| `PECFG` | `0x6000`–`0x7FFF` (8 KiB) | 2048 | bit 31:16 `WPROT`（掩码 `0xFFFF0000`，写保护锁，每次修改 `LSUCEE` 时高 16 位必须同时写入 `0x504C`）；bit 0 `LSUCEE`（`0x00000001`，加载/存储单元条件执行使能） |
| `PROG` | `0x8000`–`0xFFFF` (32 KiB) | 8192 | bit 30:0 `PROGREG`（掩码 `0x7FFFFFFF`）。PE 程序存储器窗口。每颗 PE 物理代码 RAM 容量为 16 KiB（2048 条 64 位指令），数据 RAM 容量为 12 KiB（1536 个 64 位字） |

## 2. 硬件虚拟机 (`VM00`–`VM52`) 与线程组织

每颗 PE 内部包含 3 台硬件虚拟机（Virtual Machine）：`VMx0`、`VMx1`、`VMx2`。6 颗 PE 共计 18 台虚拟机（`VM00`–`VM52`）。在 32 位虚拟机控制字中，每颗 PE 分配 1 个半字节（4 位），其中低 3 位对应 `VMx0`–`VMx2`，最高位（bit 3）未用：

| PE 编号 | 虚拟机标识 | 控制字位号 (`4 * pe_idx + vm_idx`) | 单颗 PE 虚拟机组掩码 (`0x7 << (pe_idx * 4)`) |
| --- | --- | --- | --- |
| PE0 | `VM00`、`VM01`、`VM02` | bit 0、1、2 | `0x00000007` |
| PE1 | `VM10`、`VM11`、`VM12` | bit 4、5、6 | `0x00000070` |
| PE2 | `VM20`、`VM21`、`VM22` | bit 8、9、10 | `0x00000700` |
| PE3 | `VM30`、`VM31`、`VM32` | bit 12、13、14 | `0x00007000` |
| PE4 | `VM40`、`VM41`、`VM42` | bit 16、17、18 | `0x00070000` |
| PE5 | `VM50`、`VM51`、`VM52` | bit 20、21、22 | `0x00700000` |

- 全芯片 18 台虚拟机的组合掩码为 `0x00777777`。
- `PCTRL` 的寄存器位定义将每台 `Virtual Machine n.m` 关联至 4 个子线程标识 `Thread n.m.0`–`Thread n.m.3`；而每颗 PE 的物理硬件线程槽数为 8（6 颗 PE 共 48 个线程），总线程资源宏另定义为 56。这三种编号/计数不能直接等同；寄存器可编码的子线程标识不证明每个 VM 都实现 4 个独立物理线程。
- 在全局信号唤醒寄存器 `ISIG0`–`ISIG2` 中，PE0–PE5 的首个管理线程（`THREAD_n_0_0`）按步长 16 排布在信号线 0、16、32、48、64、80 上。

## 3. PCTRL 处理器控制单元 (`0x1D600000`)

`PCTRL` 位于物理基址 `0x1D600000`，窗口长度 `0x200`，集中管理全部 18 台虚拟机的启停、休眠状态、单步调试、断点、全局定时器及线程信号：

| 字节偏移 | 寄存器名 | 访问属性 | 硬件功能说明 |
| --- | --- | --- | --- |
| `0x00` | `TCTRL0` | R/W | 虚拟机使能控制（`EN00`–`EN52`，掩码 `0x00777777`）。清 0 暂停对应 VM 上的全部线程；置 1 从暂停指令处恢复执行 |
| `0x10` | `TSTAT0` | RO | 虚拟机运行状态（`T00`–`T52`）。`1` 表示运行态（RUN）；`0` 表示 VM 执行 `SLEEP` 指令后处于空闲态（IDLE），内部事件可将其唤醒 |
| `0x20` | `TSTEP0` | WO | 虚拟机单步触发（`S00`–`S52`）。当 VM 处于暂停态时，对相应位写 1 使当前线程前进一条指令 |
| `0x30` | `TDEBUG0` | R/W | 虚拟机调试模式（`S00`–`S52`）。置 1 切入调试模式，线程取指忽略 PC，固定从程序存储器地址 0 取指 |
| `0x40` | `BCTRL0` | R/W | 断点控制寄存器。置 1 时当前线程执行到带断点指令即暂停；清 0 时忽略断点 |
| `0x50` | `BSTAT0` | R/W1C | 断点命中状态寄存器。命中断点时对应位置 1，线程在该指令处持续循环直至 VM 被暂停 |
| `0x60` | `BDIS0` | R/W | 断点连带停止寄存器。配置任一断点命中时自动置位 `TSTOP0` 冻结的 VM 掩码 |
| `0x70`–`0x7C` | `ICTRL0`–`ICTRL3` | R/W | 中断控制寄存器 0–3（共 128 位），使能 `ISTAT0`–`ISTAT3` 对应位的 CPU 中断。`ICTRL1`–`ICTRL3` 为影子寄存器，写入值仅在写 `ICTRL0` 时一并生效 |
| `0x80`–`0x8C` | `ISTAT0`–`ISTAT3` | R/W1C | 中断状态寄存器 0–3。反映全部 PCTRL 信号状态，写 1 清零；信号 `i` 同时连至线程 `i` 的中断输入 0 |
| `0x90`–`0x9C` | `ISIG0`–`ISIG3` | WO | 中断信号触发寄存器 0–3。用于发出 PCTRL 全局唤醒信号。`ISIG1`–`ISIG3` 为影子寄存器，信号仅在写 `ISIG0` 时发出 |
| `0xA0` | `TICTRL` | R/W | 全局定时器控制寄存器 |
| `0xA4` | `TICMP` | R/W | 全局定时器比较值寄存器 |
| `0xA8` | `TIDATA` | R/W | 全局定时器当前计数值寄存器 |
| `0xB0`–`0xBC` | `TIDMASK0`–`TIDMASK3` | R/W | 定时器中断目标信号掩码 0–3。`TIDMASK1`–`TIDMASK3` 为影子寄存器，写 `TIDMASK0` 生效 |
| `0xC0` | `TERR` | R/W1C | 虚拟机硬件错误状态寄存器，写 1 清零 |
| `0xD0` | `TERRMASK` | R/W | `TERR` 错误中断掩码寄存器 |
| `0xE0` | `TSESTAT` | RO | TSE 协处理器活动状态寄存器 |
| `0xF0` | `TSESTEP` | WO | TSE 单步控制寄存器。COP 跟踪模式开启时，对相应 COP 位写 1 使微码前进一条指令并将内部状态发往 `LINK2` |
| `0x100` | `AUXEN` | R/W | 辅助外部信号输入（`AUX0/LTIMER`、`AUX1/LTIMER`）使能寄存器 |
| `0x104` | `LINKRST` | R/W | 片上 `LINK` 端口网络复位控制 |
| `0x108` | `TSTEPCNT` | R/W | 单步执行步数配置寄存器 |
| `0x110` | `TSTOP0` | R/W | 虚拟机强制停止寄存器（优先级高于 `TCTRL0`） |
| `0x120` | `MCTRL` | R/W | 全部 PE 程序 RAM 的 MBIST 自检控制 |
| `0x124`–`0x138` | `MSTAT0`–`MSTAT5` | RO | PE0–PE5 程序 RAM 的 MBIST 测试签名结果 |

## 4. PE 固件装载与 DISP / MERGE 协同

6 颗 PE 装载同一份代码与初始数据映像（`falcon_gpe_fw.bin`）。单颗 PE（索引 `idx` 0..5）的硬件装载流程如下：

1. **暂停并切入调试态**：清零 `PCTRL.TCTRL0` 中该 PE 的 3 个 VM 位（`0x7 << (idx * 4)`），置位 `PCTRL.TDEBUG0` 对应位，清零 `BCTRL0` 并写 1 清除 `BSTAT0`。
2. **硬件复位**：通过 `SYS_GPE` 触发 `PE0 << idx` 的复位与激活。
3. **清空主机邮箱**：向 `PE[idx].HOST[0]` 写 0。
4. **写入程序存储器**：将固件按 32 位字顺序写入 `PE[idx].PROG[0 .. len-1]`。
5. **开启断点与中断**：置位 `PCTRL.BCTRL0`，向 `ICTRL0`–`ICTRL3` 置位中断掩码 `0x03FF87FF`（最后写 `ICTRL0` 使影子寄存器生效），置位 `PCTRL.TCTRL0` 启动虚拟机。

PE 外围的输入分发与输出汇聚由 `DISP`（`0x1D600500`）和 `MERGE`（`0x1D600600`）完成：

- **DISP（Dispatcher）**：监控各 VM 的接收就绪状态，将线程请求汇总通知 `IQM`，由 `DISP.CTRL.ACT` 位控制状态机启停。
- **MERGE（Merger）**：启用前需向 `MERGE.CTRL` 置位 `INITSTART` 执行内部 RAM 初始化，等待 `MERGE.CTRL.INITDONE` 置 1 后，再置位 `MERGE.CTRL.ACT` 开启发送仲裁。
